# OpenFilm asset adapter contract

The future adapter accepts a private run ID, a versioned brief (format, dimensions, duration where applicable, content and rights requirements), a versioned project reference and a private output location. It returns project/version, output reference and SHA-256, attempt number, and a terminal or pending state. The runner persists all of these privately; it must not put customer assets, project contents, credentials or provider keys in public Git history. A change to the brief or project invalidates dependent assets and review. Cancellation must stop active work before recording a terminal cancellation. An uncertain render result must be inspected before retrying. A configured finite retry limit applies to known failures only; `render_decision` is a policy helper, not a process manager.

Official CLI documentation specifies `openfilm look [what] [t | a-b]` for PNGs under `.film/cache/look/`, and `openfilm render [a-b]` for MP4, with `--out <file>` available. Calls operate on the project around the current folder. See https://openfilm.dev/docs/cli/. This contract does not execute those commands: presence, headless operation, isolation, output paths and cancellation on the Coolify host remain unverified. Never use `npx` to fetch software at runtime or call media-provider commands without separate authorization. OpenFilm documents that local browser-drawn graphics and supplied media can be rendered without a service, while generated media can use separately billed providers: https://openfilm.dev/docs/services/.

`assets.verify_asset` independently checks private-path confinement, output hash, matching brief and project versions, dimensions and, for MP4, ffprobe metadata and duration. PNG checks validate its signature, chunk boundaries and checksums; they do not fully decode pixels. MP4 checks inspect metadata and do not fully decode video. Neither validates visual content, audio, accessibility, licensing, safety or rights. A technical pass returns `awaiting_review`, never a final pass. An independent human or implemented independent visual/rights verifier must review the actual output and record evidence before it becomes review-ready. `ffprobe` must be locally available for MP4; unavailable tools and malformed outputs block. The runner must ensure the hashed input is immutable between verification and use; technical verification is not an atomic file lock.

Suggested handoff: brief reference/version; project reference/version; output reference/hash; attempt and cancellation state; verifier identity and evidence; content/rights review disposition; current-version comparison. Stale, missing, unavailable, or failed evidence blocks readiness. An OpenFilm asset may be omitted from a review package only with an explicit blocked state; other text work can continue. No automatic publication.
