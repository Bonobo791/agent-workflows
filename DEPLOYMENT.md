# Private deployment preparation

The supplied container runs an owner-only Unix-socket control service and exposes no HTTP listener. The worker rejects live mode, but separately configured private control actions can access task services or a Docker controller; the mode flag is not a network sandbox. Codex credential delivery, source-tool authority and real PR authority remain unavailable. The service is not a production workflow deployment, and no Coolify deployment has been tested.

For a private test, provision a data directory owned by UID 10001 with mode 0700 and a separately provisioned control-secret file owned by UID 10001 with mode 0600. The secret must be a long randomly generated value. Mount both privately; set `CONTROL_SECRET_FILE` to its container path and `WORKFLOW_DATA_DIR` to the private data mount. No credential is generated or copied by this project. Do not commit or log the secret. `python -m runner.cli` reads a single JSON request on stdin and connects to the private socket; a successful claim response contains a sensitive lease token and must not be shared or logged. Supported actions include create, enqueue, job status, cancellation request, claim, renew, release, status, JSON artifact retrieval and freeze approval. A cancellation request fences workflow writes but cannot terminate a worker without the unimplemented independent lifecycle controller. The control socket itself is owner-only. A stale socket after an unclean shutdown needs operator inspection and removal.

Before enabling real work: implement trusted integrations and an independently reviewed authorization model, safe process-tree isolation, verified fixed-origin OAuth/JWKS exchange and refresh, a supported Codex runtime, skill and evidence validation, durable backups, and all external action gates. Review storage, remote access and data isolation before changing the disabled network. The included Compose file does not expose ports and does not install Codex. It is not a finished Coolify deployment.

The selected Codex app-server integration is experimental and not supported for production workloads according to [OpenAI's app-server documentation](https://developers.openai.com/codex/app-server). A future private pilot requires a pinned app-server version and separately validated OAuth, storage, mount, network and lifecycle boundaries; local fake-protocol tests do not establish production readiness. Persistent homes, credentials and host permissions have not been provisioned or validated.
